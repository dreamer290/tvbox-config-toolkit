零、安装「配置失败」的根因与修复

初版配置在客户端加载时报「配置失败」，逐项复现后定位到两个自身缺陷和一个操作误区，均已修复。

问题为什么会导致失败修复方式
42 个站点的 ext 写成了 JSON 对象
致命		 TVBox 的 Site.ext 是 String 字段。Gson 反序列化 {"host":"..."} 到 String 时抛 Expected a string but was BEGIN_OBJECT，解析在第一个这样的站点处中断，整个配置被判为无效。 全部压成紧凑 JSON 字符串（"ext": "{"host":"..."}"），两种内核都能读。
30 个站点 api 用相对路径
站点级失效		 原仓库的 ./lib/drpy2.min.js、./py/xxx.py 依赖发布者的目录结构，配置拷到本地后必然 404， 在电视上表现为一批点不开的空壳站点。 剔除这 32 个站点（标准 TVBox 内核本就不支持 py 站），站点数 176 → 146。
配置地址填成 /sdcard/...
操作误区		 客户端用 OkHttp 拉配置，裸文件路径和 file:// 都会抛协议异常，同样只显示「配置失败」。 改为局域网 HTTP（serve.py）或 clan://localhost/... 加载。

修复后已通过静态模型体检：146 个站点的 key/name/api/type/ext 类型、重复 key、spider 站点的 csp_* 前缀、直播与解析的字段类型，全部符合 TVBox 数据模型。

一、结论先说

  • 能用的点播源集中在 macCMS 采集接口：39 个接口用「庆余年」实测搜索，都能返回带 vod_play_url 的片源，其中 13 个只认 ac=videolist 参数（TVBox 本身两种都会试，不影响使用）。
  • 直播可用率不到四成，但质量高的很集中：49 个直播源里 18 个能解析出频道，真正稳定的是「IPTV自动更新」「24live」「平台直播」三家；据此逐台竞速挑选，得到 53 个连分片都拉得下来的频道（CCTV 全套 + 全部省级卫视）。
  • 解析（VIP 解析）几乎全线失效：78 个里只有 8 个 HTML 嗅探型还能返回直链，JSON 型接口 100% 不可用——这类接口普遍是个人 IP:端口 服务，存活期只有几周。
  • spider jar 是点播的另一半命脉：22 个 jar 里 18 个可下载且 MD5 与配置声明一致。最终配置选用「潇洒」的 spider.jar（1.8MB，19 个通用类命中 17 个）。

二、验证方法（四层递进）

1 · 配置层：能不能拿到

直接 HTTP 抓取，校验状态码、体积、JSON 结构（含 // 注释、尾逗号这些 TVBox 容忍但标准 JSON 不容忍的写法）。

2 · 结构层：里面有什么

统计 sites / lives / parses 数量与类型（0=XML、1=JSON、3=spider），相对路径 ./jar/x.jar 一律还原成绝对地址再验证。

3 · 功能层：真的能用吗

采集源：真实搜索「庆余年」，要求返回片源且带播放地址（不是只看 HTTP 200）。
直播源：解析频道列表 → 随机抽 4 个频道试播 → 记录可播比例。
jar：下载后校验 PK 文件头 + 与配置声明的 MD5 比对。

4 · 深度层：验证到可播放

精选频道逐个拉取 m3u8 → 解析子列表 → 实际下载首个 TS 分片，确认拿到大于 800 字节的媒体数据，排除「列表假活、分片已死」。

六、验证的边界

  • spider 站点（107 个）无法在桌面端逐站验证。它们靠 jar 内的 JS/dex 在播放器里跑，只能在 TVBox 客户端里生效。本次能做的极限是：验证 jar 可下载、MD5 与声明一致、站点引用的 csp_* 类属于该 jar 的通用集合（19 个经典类命中 17 个）。
  • 网络位置会改变结论。本报告全部从这台机器（家庭宽带）发起；换运营商、换省份、开 IPv6，结果会有出入。失效的源里有一部分是被 DNS 污染误伤，不代表源站已死。
  • 时效性短。免费源的平均寿命以周计，采集接口换域名、直播 IP 关端口都是常态。建议每周重跑一次验证再更新配置。
  • 港澳台频道整批缺失。公共免费清单里这类频道基本已被清理，19 个目标频道（凤凰、翡翠、TVB、澳门系列等）在 18 个可用源中都没找到能播的地址——不是筛掉的，是本来就没有。
