# TVBox 本地配置（2026-10-19 实测可用版）

从 GitHub 上 20 多个 TVBox 接口仓库里抓取 21 个配置，在本机逐个实测后重新组装的一份配置。
**没有一条源是「抄来没测就写进去」的**——点播源用真实关键词搜索验证到片源，直播频道验证到 TS 分片能下载。

## 文件清单

| 文件 | 说明 |
| --- | --- |
| `tvbox-config.json` | 主配置，`spider` 和直播用同目录相对路径（`./spider.jar`、`./live.txt`） |
| `tvbox-lan.json` | 同上，但把相对路径写死成本机局域网地址，兼容不解析 `./` 的版本 |
| `tvbox-online.json` | 单文件版，不依赖任何本地文件，直接填 URL 就能用 |
| `live.txt` | 53 个逐台验证过的直播频道 |
| `spider.jar` | spider 本地副本，1.8 MB，MD5 `bbb5214a2ba3724821c5f8d2db5071dc` |
| `verify.py` | 自检脚本，纯标准库，随时复验这份配置现在还能不能用 |
| `验证报告.html` | 完整验证过程与数据（哪些源、为什么失效、怎么筛的） |

## 上一版为什么会「配置失败」

已定位到两个原因，这一版都修掉了：

**1. `ext` 字段写成了 JSON 对象（致命）**

TVBox 的站点模型里 `ext` 是**字符串**字段。上一版有 42 个站点的 `ext` 是 `{"host": "..."}` 这样的对象，
Gson 反序列化时抛 `Expected a string but was BEGIN_OBJECT`，客户端整体解析中断，只会显示「配置失败」。
现在这 42 个已全部压成紧凑 JSON 字符串，所有分支版本都能读。

**2. 30 个站点引用 `./lib/drpy2.min.js`、`./py/xxx.py` 这类相对路径**

这些是原仓库的目录结构，配置拷到本地后必然 404，在电视上表现为一堆点不开的空壳站点。
这一版直接剔除了这 32 个站点（普通 TVBox 内核本来也不支持 py 脚本站点），站点数从 176 调整为 146。

**3. 配置地址的填法（最常见的误操作）**

`/sdcard/TVBox/tvbox-config.json` 这种裸文件路径**多数 TVBox 分支不认**——它用 OkHttp 拉配置，
`file://` 和裸路径都会直接抛协议异常，同样只显示「配置失败」。请按下面的三种方式之一填。

## 怎么用

**① 局域网 HTTP（最稳，推荐电视盒子用）**

电脑和盒子连同一个 WiFi，在本文件夹执行：

```bash
python serve.py
```

它会打印形如 `http://192.168.31.25:9978/tvbox-config.json` 的地址，把它填进 TVBox 的配置地址即可。
配置里的 `./spider.jar`、`./live.txt` 会自动解析到同一台电脑，不用改任何路径。
如果电视提示连不上，先在电脑上用浏览器打开这个地址确认能访问，再检查 Windows 防火墙是否放行了 9978 端口。

> `tvbox-lan.json` 里写死了生成时的本机 IP（本次为 `192.168.31.25`）。换了网络或路由器重新分配 IP 后它会失效，
> 此时用 `tvbox-config.json`（相对路径，跟着配置地址走）即可，或重新生成一份。

**② 设备本地文件（可离线，需要播放器支持 `clan://`）**

把整个文件夹拷到 `/sdcard/TVBox/`，配置地址填：

```
clan://localhost/TVBox/tvbox-config.json
```

`clan://` 是 TVBox 内置的本地 HTTP 服务，只有它能读本地文件并让 `./spider.jar` 正常解析。
部分精简版删掉了这个功能，填了没反应就改用方式 ①。

**③ 单文件版（不碰电脑、不拷文件）**

配置地址直接填远程地址，用 `tvbox-online.json` 的内容部署到你自己的可访问地址，
或把 `tvbox-config.json` 里的 `spider` 换成在线地址、删掉 `./live.txt` 那条直播，效果等同。

## 内容概览

- **点播 146 个站点**：39 个 macCMS 采集源（已实测出片）+ 107 个 spider 站点（网盘/4K，依赖 jar）
- **直播 7 个入口**：本地精选 53 台 + 6 个整源（IPTV自动更新 233 台、24live 1031 台、平台直播 222 台、虎牙/斗鱼/YY 一起看）
- **解析 8 个**：全部为实测能返回直链的嗅探型

## 关于 spider 和那 107 个站点

`"type": 3` 站点的执行逻辑在 jar 里，**只能在播放器内运行，桌面脚本测不了**。
能确认的是：jar 可下载、体积对得上、MD5 与配置声明一致、引用的 `csp_*` 类属于该 jar 的通用集合（19 个经典类命中 17 个）。
所以这部分是「结构可信」，不是「逐站实测」——报告里也按这个口径写的。

## 随时复验

源的有效期很短，建议每周跑一次：

```bash
cd 配置所在目录
python verify.py
```

输出会逐条列出每个点播源、每个直播频道、每个解析的当前状态。**出现个别失败很正常**——采集接口有 WAF 限流，连续请求会临时 403，隔几分钟再跑往往又好了。

## 已知缺失

- **港澳台频道一个都没有**。凤凰、翡翠、明珠、TVB、HOY、澳视、澳门莲花等 19 个目标频道，在 18 个可用直播源里都找不到能播的地址——公共免费清单里这类频道基本已被清理，不是筛选时丢掉的。
- 点播里失效的 34 个采集源，有 11 个是 **DNS 被污染**（例如 `api.tiankongapi.com` 被解析到 Facebook 的 IP），换网络环境可能反而可用；配置里已内置阿里 / DNSPod 的 DoH，支持的播放器可开启。
